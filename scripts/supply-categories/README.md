# Товарные группы поставщиков — как это работает

Задача (владелец, 2026-09-12): «каждый поставщик поставляет только свой спектр
товара. У кого-то это десятки категорий, у кого-то сотни, у кого-то всего
несколько. Можем ли мы реализовать задачу по парсингу категорий поставки
существующим поставщикам в базе? Желательно, не через проксиапи, он дорого
обходится, а через самую экономную модель в рамках моего тарифа Max x20».

Поэтому конвейер разделён на два шага, и ProxyAPI не участвует ни в одном.

## Шаг 1 — снимок сайта, без ИИ (работает сам)

Edge Function `process-supplier-jobs` (крон раз в минуту) разбирает очередь
`supplier_site_snapshots`: скачивает главную, корень каталога и `sitemap.xml`,
вытаскивает названия и адреса разделов каталога. Модели здесь нет вовсе —
обычный разбор HTML, стоит ноль.

Домен в очередь ставит триггер в базе при сохранении карточки поставщика с
сайтом (`supabase/migrations/20260912-supplier-site-snapshots.sql`), поэтому
новые поставщики подхватываются сами, ничего запускать не надо.

Строка — на **домен**, не на карточку: одна компания живёт в нескольких
категориях закупок (278 карточек / 259 доменов), а сайт у неё один.

## Шаг 2 — классификация в сессии Claude Code (в рамках подписки)

Выполняется человеком-оператором через Claude Code, когда накопились новые
снимки (или после правки справочника). ProxyAPI не нужен, платит подписка.

```bash
node scripts/supply-categories/export.mjs          # только новые
node scripts/supply-categories/export.mjs --all    # всё заново
```

Появится `scripts/supply-categories/out/batch-NN.json` — по 12 сайтов в файле
(название компании, заголовок и описание главной, список разделов каталога).

Дальше — по одному субагенту (`Agent`, модель haiku) на пачку, с промптом:

> Прочитай `scripts/supply-categories/out/batch-NN.json`. Для каждого сайта
> определи, какие товарные группы из справочника `src/data/supplyCategories.ts`
> компания реально поставляет — по разделам её каталога, а не по догадкам.
> Бери только те группы, под которые в разделах есть явные позиции. Если сайт
> универсальный магазин стройматериалов — ставь «Строительный гипермаркет
> (всё для ремонта)» плюс те группы, что действительно широко представлены.
> Если по разделам не понять — оставь пустой массив. Запиши результат в
> `scripts/supply-categories/out/result-NN.json` массивом
> `[{"host": "...", "categories": ["..."], "note": "одна строка: чем компания
> занимается"}]`. Названия групп — дословно из справочника. Если какой-то
> группы явно не хватает, упомяни её в note, но в categories не пиши.

Потом:

```bash
node scripts/supply-categories/import.mjs --dry   # посмотреть, что запишется
node scripts/supply-categories/import.mjs
```

Импорт сверяет группы со справочником: незнакомые в базу не идут, а
печатаются списком — это кандидаты в `src/data/supplyCategories.ts`. После
правки справочника имеет смысл переклассифицировать всё (`export --all`).

## Где это видно

Страница «Поставщики»: группы чипами в списке под каждым поставщиком
(первые четыре) и полным набором с заметкой в карточке «Подробнее», блок
«Что поставляет».

## Зачем

Главное — не сама разметка, а то, что при заведении новой категории закупки
видно, кто из уже известных поставщиков её закрывает, без нового веб-поиска
(одно задание поиска через ProxyAPI стоило ~195 ₽, см. журнал за 2026-09-11).
Плюс массовая рассылка по категории может идти только тем универсальным
поставщикам, у кого есть нужная группа, а не всем подряд.
