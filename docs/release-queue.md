# Очередь релиза

Накопитель готовой, но ещё не опубликованной работы. Владелец ведёт несколько
диалогов параллельно, каждый доводит свою фичу до готовности и **останавливается
перед публикацией**; потом всё накопленное уезжает в прод **одним мерджем = одним
билдом Vercel**.

Правила работы с этим файлом — в `CLAUDE.md`, раздел "Очередь релиза". Коротко:

- сессия дописывает СВОЮ запись в "Ждут публикации" сверху, на своей ветке,
  и на этом заканчивает — в `oodobu` ничего не пушит;
- публикующая сессия собирает все перечисленные ветки в одну релизную,
  прогоняет сборку и открывает ОДИН PR в `oodobu`;
- после публикации записи переезжают в "Опубликовано" (внизу), не удаляются.

Конфликт в этом файле при мердже (две сессии дописали сверху) разрешается как
в журнале — **сохранять обе записи**, не выбирая сторону.

### claude/optimistic-ramanujan-69f6jz
- **Что:** индикатор "N онлайн на сайте сейчас" в админке — под логотипом,
  справа от имени пользователя в Sidebar. Видно только Трэшмену (гейт
  `isSuperAdminAllowed`, тот же, что у пункта меню "Метрики"). Реализовано
  через Supabase Realtime Presence (`src/lib/onlinePresence.ts`): все
  маркетинговые страницы (всё, что не под `/admin` — джойн условие в
  `App.tsx`, тот же критерий, что уже использует хук pageview-хитов Метрики/
  VK-пикселя) джойнятся в общий канал `online-visitors` под случайным ключом
  на вкладку; Sidebar слушает `presence sync` того же канала и считает
  участников, сам не трекается (открытая CRM не прибавляет единицу к
  счётчику). Ни своей таблицы, ни поллинга — обновление по сокету, почти
  мгновенное.
- **Проверено:** `npm run build:app` чистый (`tsc -b` без ошибок). Живой
  прогон presence через реальный Supabase-сокет в этой сессии не делался —
  сетевой прокси окружения не проверялся на WebSocket до `*.supabase.co`;
  сама реализация — стандартный API `@supabase/supabase-js` v2
  (`channel.track`/`channel.on('presence',{event:'sync'})`/
  `presenceState()`), без исторических прецедентов realtime-канала в этом
  репозитории (grep `.channel(` до этой ветки — пусто), так что при
  публикации стоит один раз открыть публичную страницу и `/admin` рядом и
  проверить счётчик глазами.
- **Миграции SQL:** нет — presence не трогает БД вовсе, только in-memory
  realtime-сервер Supabase.
- **Риск при задержке:** нет, чисто аддитивная фича без миграций.
- **Конфликты при сборке:** маловероятны — новый файл
  `src/lib/onlinePresence.ts` + точечные правки в `src/App.tsx` (два новых
  хука рядом с существующими `useSpaPageviewHits`/`useVkPageGoals`) и
  `src/components/layout/Sidebar.tsx` (блок под логотипом, рядом с
  `profile.displayName`).
